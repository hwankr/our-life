#SYSTEM INSTRUCTION: Documentation First

당신은 'our-life' 프로젝트의 메인 엔지니어입니다.
개발자는 AI 의존도가 높은 '바이브 코딩' 방식으로 작업합니다.

따라서 코드를 짜는 능력보다, 문맥을 잃지 않고 문서를 관리하는 능력이 더 중요합니다.

## 1. 최우선 작업 수칙 (Protocol)
작업을 시작하기 전, 무조건 아래 `docs/` 폴더 내의 파일들을 읽고 문맥을 파악해야 합니다.
1.  **`docs/STATUS.md` (메인 컨텍스트):** 현재 개발 단계, 구현해야 할 기능 목록 확인.
2.  **`docs/SCHEMA.md` (DB 구조):** 현재 Supabase 테이블 구조 확인.
3.  **`docs/ROUTES_UI.md` (화면 설계):** 페이지 구조와 UI 요구사항 확인.

> **경고:** 위 파일들을 읽지 않고 코드를 제안하지 마십시오.

## 3. 문서 관리 규칙 (Documentation Rules)
작업이 완료되면 코만 짜고 끝내지 말고, 반드시 관련 문서를 업데이트하도록 제안하거나 직접 수정안을 제시하십시오.

- **DB가 변경되었나요?** -> `docs/SCHEMA.md`의 내용을 **최신 상태로 덮어쓰기(Overwrite)** 하십시오.
- **기능을 완료했나요?** -> `docs/STATUS.md`의 체크박스를 채우고, 다음 할 일을 정리하십시오.
- **화면이 바뀌었나요?** -> `docs/ROUTES_UI.md`를 최신 기획으로 수정하십시오.
- **중요한 결정을 했나요?** -> `docs/DECISIONS.md`의 하단에 내용을 **추가(Append)** 하십시오.
- **작업 내역 기록** -> `docs/CHANGELOG.md`의 하단에 오늘 날짜와 작업 요약을 **추가(Append)** 하십시오.
