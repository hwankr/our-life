## 2026-02-01: 프로젝트 초기 설계

### 1. 기술 스택 선택

**결정**: Supabase + Next.js (App Router)

**이유**:
- 혼자 빠르게 개발하기에 BaaS(Backend as a Service)가 적합
- 인증, DB, 실시간 기능이 한 곳에서 해결
- Prisma 방식보다 초기 설정이 간단
- 무료 티어가 충분함

**대안**: Prisma + PostgreSQL + NextAuth (기각: 초기 설정 복잡)

---

### 2. Goal 타입별 스키마 설계

**결정**: 단일 테이블 + optional fields

**이유**:
- 3가지 타입(ROUTINE, LIMIT, OBJECTIVE)이 공유하는 필드가 많음
- 서브타입 테이블 분리는 과도한 복잡성
- JSON 컬럼으로 타입별 추가 데이터 저장

**대안 1**: 서브타입 테이블 분리 (기각: 조인 복잡)
**대안 2**: 전체 JSON 컬럼 (기각: 쿼리/검증 어려움)

---

### 3. LIMIT 월별 집계 방식

**결정**: 조회 시 GoalLog에서 집계 계산 (MVP)

**이유**:
- MonthlySnapshot 테이블 관리 오버헤드 줄임
- 데이터 양이 적어 성능 문제 없음

**추후**: 성능 이슈 시 월별 스냅샷 테이블 도입

---

### 4. 같은 날짜 중복 체크 정책

**결정**: (사용자 확인 필요)
- ROUTINE: 하루에 1회만 (UNIQUE 제약)
- LIMIT: 하루에 여러 번 가능 vs 1회만
